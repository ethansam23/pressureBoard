# Reference streams

Generated by `test_link_frame --emit-ref`, i.e. by the **same
`sim_profile_code()` the firmware runs** — that is the whole reason the profile
lives in the pure protocol core.

These are committed deliberately. The bench PC runs Keil and Python but has no
C toolchain, and requiring one there would put a compiler between the operator
and a test run. `soak_verify.py` consumes these directly:

```
python soak_verify.py --capture logs/run1 --reference ../host_tests/refs/phaseB_rate1000.csv --rate 1000
```

| File | Phase | RATE | Refreshes | Used by |
|---|---|---|---|---|
| `phaseB_rate1000.csv` | B — timing ladder | 1000 ms | 3,600 | Test B / campaign Phase 2 |
| `phaseA_rate1000.csv` | A — resolution sweep | 1000 ms | 20,600 | Test A / Phase 3 |
| `full_rate1000.csv` | FULL — 24 h | 1000 ms | 86,400 | Tests D / Phases 5, 7 |
| `phaseB_rate100.csv` | B — timing ladder | 100 ms | 36,000 | Test C |

**Do not hand-edit.** `make -C host_tests` regenerates them into a temp
directory and fails if they no longer match the code, so drift is caught by
anyone who has gcc. To refresh after a deliberate profile change:

```
make -C host_tests refs
```
