# Host tools — downhole link (9600 8N1 on P1.0)

Three tools, for three different jobs:

| Tool | Job |
|---|---|
| `pressure_monitor.py` | Live GUI: decodes the packet stream, and opens a bench console when you ask it to |
| `soak_capture.py` | Headless long-run capture — raw bytes + timestamps, nothing else |
| `soak_verify.py` | Scores a capture against the firmware's own reference stream |

`link_decoder.py` is the shared, I/O-free packet decoder the first and third
both use.

## Setup (one time)
```
pip install -r requirements.txt
```
(installs `customtkinter` + `pyserial`)

## Wiring

One USB-UART adapter does both directions — TX and RX are separate pins:

```
board TX P1.0 ──────► adapter RX      (the packet stream)
board RX P1.1 ◄────── adapter TX      (console commands)
                GND ── common
```

**The adapter must signal at 5 V.** P1.0 drives ≥ 4.6 V into your adapter's RX,
and P1.1 needs ≥ 3.5 V to read a logic high. See `../verification_guide.md`
for the numbers.

## `pressure_monitor.py` — live monitor

```
python pressure_monitor.py
```

**Passive by default: it never transmits until you opt in.** Pick the COM port,
hit Connect, and it decodes packets — pressure in bar, the 16-bit wire code,
packet rate, checksum errors, and a staleness indicator.

**Bench Mode** (behind a confirmation) sends `CONSOLE UNLOCK`, which
**suspends the packet stream** — a connected logger sees the line go quiet.
Leaving Bench Mode sends `CONSOLE LOCK` and the stream resumes. While unlocked
you can run any console command (`STATUS`, `CAL ARM`, `LINKTEST 10000`,
`SIM BAR`); see `../uart_command_reference.md` for the full set.

Debug firmware only — a production build (`LINK_CONSOLE_EN=0`) has no console
and will not answer.

## `soak_capture.py` — long-run capture

```
# arm the board and capture in one step
python soak_capture.py --port COM5 --out logs/run1 --arm --sim BAR --phase FULL

# or capture only, having armed elsewhere
python soak_capture.py --port COM5 --out logs/run1 --hours 24
```

Records raw wire bytes plus a `.idx` sidecar of arrival timestamps, rotating
across parts, reconnecting across USB re-enumeration. It does **not** decode —
a capture tool that also interprets is one that can lose evidence when its
interpretation is wrong.

Without `--arm` it never transmits. With `--arm` it transmits once (unlock →
`SIM …` → verify RATE → lock), latches TX off permanently, then confirms
packets are really flowing before committing to a long run — which turns the
classic own-goal, a suspended stream and 24 hours of silence, into an error in
the first ten seconds.

It deliberately never sends `RATE`: that writes NVM. It reads the board's rate
and aborts on a mismatch instead.

## `soak_verify.py` — scoring

```
make -C ../host_tests
../host_tests/test_link_frame --emit-ref ref.csv 1000 0     # rate_ms, phase
python soak_verify.py --capture logs/run1 --reference ref.csv --rate 1000
```

The reference is generated by the **same function the firmware runs** (the
profile lives in the pure protocol core, which `host_tests/` compiles under
gcc), so there is no reimplementation to drift.

Reports resolution coverage (all 10,001 deci-bar codes), value-exact comparison
against the reference, per-ramp duration measured by counting packets, gaps,
checksum errors, and board resets. Exit code 0 = PASS.

Phases: `0` = FULL (24 h), `1` = Phase A resolution sweep, `2` = one Phase B
ladder cycle.

## Tests

```
python -m unittest discover .
```
Covers the decoder (including a cross-check against `host_tests/golden_stream.csv`,
so the C encoder and the Python decoder are tested against each other) and the
verifier (synthetic captures with injected drops, short runs, corrupted
checksums, and start beacons).
